# Mood Mascot, Daily Reminders, and Popup Shell V1

## Final supplied-art and Android delivery revision - 2026-09-05

- The newer 1536x1024 transparent mood sheet is preserved as `assets/character/mascot_mood_sheet_source_v2.png`. It contains twelve poses per mood, not eight. The runtime now uses 24 consistently registered 160x160 circular crops; `MascotView.FRAME_COUNT` is 12 and its glide speed is retuned to 2.15 track units/second, producing more intermediate motion without changing reaction authority.
- The originally supplied sheet remains preserved. The v2 derivative is regenerated by `scripts/dev/slice_mascot_frames.gd`; source pixels never define gameplay state or physics.
- The supplied transparent logo and illustrated-background logo are preserved separately under `assets/logo/` and copied pixel-for-pixel to their matching runtime roles. Transparent never substitutes for background and background never substitutes for transparent.
- The engine splash now uses a purple radial gradient with the supplied transparent logo at medium size in the center. The mascot is deliberately absent from the splash. Android's short native system splash also uses the transparent logo over the matching dark edge color before the engine gradient appears.
- Mobile map scrolling is no longer left solely to `ScrollContainer` gesture capture: `LevelMapView` handles `InputEventScreenDrag` and moves its owning scroll container directly, while keeping taps release-based and movement-gated.
- The notification bridge is now compiled from `android/build/src/main/java`, registered as the `MajesticNotifications` Godot v2 singleton, declares `POST_NOTIFICATIONS`, registers the alarm receiver, and is enabled for both Android presets. The pure scheduling tests remain the authority for timing/state decisions; build validation checks the native classes and manifest.

**Date:** 2026-09-05
**Scope:** the crowned-gem mascot as a reactive mood dial across four screens,
one shared popup title treatment that animates with its popup, and a local daily
reminder for unclaimed missions with a settings toggle.

## 1. Slicing the supplied sheet

The sheet arrived as a single transparent PNG, 1672x941, two rows of eight.
Measured rather than assumed:

| | |
| --- | --- |
| Column centres | 112, 319, 525, 732, 938, 1144, 1351, 1557 (pitch 206.4) |
| Row centres | 272, 646 |
| Coin half-width | 103 px (alpha falls to ~0 at x-offset 104) |
| Coin half-height | 107 px |

**Neighbouring coins touch.** At a 206.4 pitch and ~206 width there is no gap, so
a plain square crop carries a crescent of the next coin's gold rim into every
frame. An elliptical 103x107 mask with a 1.5px feather removes the neighbours
completely, and the raised hands in the late happy frames sit inside it - checked
by comparing the end frames, which have one neighbour, against the middle ones,
which have two.

**Frames are cut on the even grid, not on per-frame bounding boxes.** A bounding
box moves when the character raises its hands; cropping to it would make the head
jitter between poses. Every frame is written at 224x224 with the coin on the same
centre, and the test asserts all sixteen share one size, because shared size *is*
the registration.

`scripts/dev/slice_mascot_frames.gd` reproduces the frames from the original on
demand. The source sheet is preserved at
`assets/character/mascot_mood_sheet_source.png`; only derivatives live under
`assets/runtime/character/`.

## 2. Making eight frames read as animation

The brief was "make sure the animation looks smooth and not like different
images". Eight frames is not many, so two things do the work.

**Position along a track is a float, eased toward a target.** Callers set a mood
and an intensity; the view glides. A jump from idle to happiest travels through
every intermediate pose instead of cutting to the end. The test asserts this
directly - it samples the frame across the glide and requires the middle of the
track to actually be visited.

**Adjacent frames cross-fade, base opaque.**

```gdscript
draw_texture_rect(frames[lower], rect, false)
if upper != lower and blend > 0.0:
	draw_texture_rect(frames[upper], rect, false, Color(1, 1, 1, blend))
```

Drawing both at complementary alphas is the intuitive approach and is wrong. The
gold ring is identical in every frame; two half-opaque copies of it leave it
about 75% opaque, so the whole mascot visibly dims at every blend midpoint.
Drawing the lower frame opaque keeps the ring solid while the face cross-fades.

**Track changes rewind through neutral.** Happy and sad are separate tracks that
share only the first pose, so `set_mood` mid-expression queues the new mood, runs
back to neutral, and then applies it. A direct swap would cut the face.

A small idle breath (2.2% scale, 1% bob) keeps it alive when settled. It is
deliberately tiny - the HUD mascot sits next to live gameplay and must not pull
the eye off the board.

## 3. Where it appears

| Screen | Behaviour | Size |
| --- | --- | --- |
| Result popup | happy 1.0 on a win, sad 1.0 on a loss, sad 0.6 on the rescue offer | 300 px |
| Level Ready | neutral, replacing the target readout | 240 px |
| Level briefing | neutral | 260 px |
| Gameplay HUD | reacts to play, at the right end of the Target plate | 100 px |
| Level select | neutral, header right | 96 px |

These are the final placements; section 8 records how they got there.

**No popup shows a target readout any more.** The result screen used to show the
target gem on a win and a timer badge on a loss; neither said anything the title
and the reward card did not already say.

In-game reactions come off the same beats the analytics record - merge, combo
(scaled by chain depth), win, fail - so the expression cannot drift from what the
game thinks happened. In-play beats hold ~0.9s then decay to neutral so the
mascot is ready for the next merge; win and fail do not decay, because the result
popup lands on top of them and should match.

**One layout constraint worth recording.** `objective_stack_anchor` (the target
card and the merge path) is a separately anchored container that draws over the
top utility row and whose vertical position tracks the table. Two HUD placements
were rejected because of it - see section 8. The mascot ended up inside the
Target plate itself, which is the one spot that is both central and already part
of that stack.

## 4. The popup label bug

**Reported:** the label appears before the popup and disappears after it.

**Cause:** the half-out gold banner is a *sibling* of the panel - it has to be,
because it overlaps the panel's top edge - and every popup tweened the panel:

```
center
└── title_column
    ├── banner      <- never animated
    └── panel       <- scale + modulate tweened here
```

**Fix:** `UiDesignSystem.popup_shell(title, panel)` returns both as one node with
its pivot maintained on resize, and every popup animates the shell. The contract
is enforced rather than documented: the regression asserts the panel sits inside
the shell and carries no animation of its own.

**Consistency.** Daily Missions and the Powers shop already used the half-out
banner. The result screen and the level briefing each had their own inline banner
*inside* the body and read as a different design language. All four now go
through `popup_shell()`.

## 5. The daily reminder

Local scheduled notification, not push: the reminder is about state the device
already knows, so it needs no server, no account, and works offline.

**Fires at 19:00 device-local, and only when something is outstanding.** This is
the rule the feature rests on. A reminder on a day the player already finished
everything teaches them the channel is noise, and the next one gets swiped away
with it. `should_remind()` is the single gate, and it is re-evaluated on every
mission-state change rather than once a day - so claiming the last mission at
18:55 cancels the 19:00 reminder. An unopened chest counts as outstanding,
because it is still a reason to open the game.

**Every rule is a pure function**, which is why the feature is tested at all:
whether to fire, the delay to the next 19:00 from any time of day, and the copy.
Exactly 19:00:00 returns tomorrow rather than zero, so a claim at the reminder
minute cannot fire an alarm immediately.

**Settings.** A REMINDERS toggle in Home settings, persisted separately from
audio. This surfaced a latent bug: `save_settings()` rebuilt the config file from
scratch and silently dropped any key it did not take as a parameter, so an audio
toggle would have wiped the notification preference. It now loads first.

**Native side.** `android/plugins/majestic_notifications/` holds a Godot plugin
singleton and an alarm receiver. Inexact alarms on purpose - exact alarms need
`SCHEDULE_EXACT_ALARM`, which Play grants only to alarm and timer apps, and a
missions reminder does not need second accuracy. One stable id with
`FLAG_UPDATE_CURRENT` so frequent reschedules replace rather than stack.

## 7. Not done, and what is unverified

- **The Android plugin has never been compiled or run.** It is not wired into the
  build - no gradle module, no manifest permission, no receiver registration, not
  enabled in `export_presets.cfg`. Until that is done the game schedules nothing
  and every call is a no-op, which *is* tested. Wiring steps are in the plugin
  README. **The Java itself is unverified in every respect.**
- **No boot receiver.** Alarms do not survive a reboot, so a device restarted
  before 19:00 misses that day and is rescheduled the next time the game runs.
- **Placeholder notification icon.** `android.R.drawable.star_on` stands in for a
  real monochrome silhouette at five density buckets.
- **No Android build, no device.** Everything above was verified headless and
  through rendered captures at 720x1440.
- **The mascot is upscaled in popups.** Source frames are 224px after slicing
  (the coin is ~206px in the supplied sheet); at 300px in the result popup that
  is a 1.4x upscale. It looks acceptable in the captures, but a higher-resolution
  sheet would be sharper.
- **The HUD mascot is tight on limited-shots levels.** It clears the objective
  stack at 74px, but that band is genuinely crowded; if SHOTS LEFT ever grows,
  this is the first thing that will collide again.

## 8. Revisions after the first review pass

Each of these came from looking at the built screen rather than from the plan.

**The popup expression did not animate.** `present()` set the mood with
`immediate: true`, which snapped straight to frame 8 - there was nothing left to
play. Popups now call `play_from_idle()`, which rewinds to frame 1 and glides,
so the idle-to-happy or idle-to-sad run is seen from the beginning every time.

**And it started too early.** Even gliding, most of the run happened while the
panel was still scaling up and half transparent. The expression is now queued at
`present()` and fired by a tween callback once the entrance has settled
(`MASCOT_REACTION_DELAY`).

**The mascot bounced in popups.** Two separate causes: the idle breathing loop,
now switched off via `breathing_enabled` wherever a popup supplies its own
entrance scale, and a `TRANS_BACK` overshoot on the result mascot's own reveal,
now a plain fade.

**The shots counter moved out of the middle of the HUD.** It sat at the top of
the centred objective stack, directly over the only space wide enough for the
mascot. It is now a compact pill under Coins, built in the Next panel's language
so the two columns flanking the centre read as a matched pair.

**The target panel is rectangular, not square.** A square plate with the mascot
above the target line was built to match the supplied mock-up and then reverted:
at 720x1280 the taller stack pushed the merge path down onto the table, which
`run_ui_scale_layout_tests` caught. The panel is a wide plate again with the
mascot at its right end, filling what used to be empty space.

**The level map did not scroll.** `LevelMapView` had `MOUSE_FILTER_STOP`, so the
`ScrollContainer` never saw the drag. It is `MOUSE_FILTER_PASS` now, and
selection moved from press to release with a movement tolerance - acting on
press meant every attempt to flick the map opened a level instead, because the
first event of a scroll is a press on whatever is under the finger.

**Decorative gems fill the map's empty side.** Drawn from a slot-seeded RNG
rather than a stored list, so nothing is allocated for a thousand levels and the
scatter is identical every time the screen opens; a map that reshuffled its
decoration while scrolling would shimmer. They are never hit-tested.

**Level Ready lost its target readout.** It showed a target badge, the target
gem and an objective line; it now shows the mascot neutral, like every other
popup.

### Test changes these forced

Four suites asserted the previous layout by name and were updated to the current
contract, not loosened:

- `run_ui_scale_layout_tests` measured Target prominence as "more than twice as
  wide as Next". Target is no longer defined by width, so it now asserts area.
- `run_level_briefing_shots_v1_tests` required the counter to be inside the
  centred objective stack and horizontally centred. It now requires the opposite
  placement - in the left column, below Coins, not overlapping Target - because
  that is where it was deliberately moved.
- The same suite required score-sized type on the count. The compact pill cannot
  carry 52px, so it now asserts the number is large in absolute terms and
  clearly dominates its own caption.
- `run_level_select_map_v1_tests` tapped with a press event only. It now sends
  press and release, and gained a case proving a drag scrolls instead of
  selecting.
