# Shared Perspective + Win Sequence Fix v1

## Architecture

The failed per-gem Y-scaling and gem-only screen-offset approaches were removed. Physics now runs in a `720 x 828` logical table rectangle. `ProjectedGameplayWorld` renders the table, gems, shadows, launcher, danger line, and merge effects into a transparent `SubViewport`; one `Polygon2D` maps that texture to the bottom-anchored screen trapezoid. HUD and result UI remain outside this projected layer.

`SharedTableProjection` supplies the inverse input mapping. Pointer positions are converted from screen to logical space before drag clamping; the same helper round-trips logical positions to screen in tests.

## Collision, depth, and win order

Approved fixed per-tier body/collider calibration remains intact. No live gem changes scale, collider, texture, or projection offset by Y. Stable local-Y then ID ordering occurs inside the shared world, with shadows behind their own gems.

The controller traces `result_created -> result_first_frame_visible -> presentation_completed -> target_completed -> win_overlay_started`. Target completion waits until the result has synchronized into the SubViewport and completed its own presentation; restart clears every pending state.
